## F3 — genuine Franc-generated isolated processes (QEMU accepted)

- `lib/user_aot.frac` is a bounded Franc-language source compiler. It recognizes the audited `def main N count fault ;` and `def main N count again ;` forms for `N=1..255`, emits actual unprivileged x86-64 bytes into a reserved 256-byte scratch span, and rejects unknown instructions/grammar.
- `stage4/user_compiled.S` does not trust an arbitrary JIT address: it audits the *entire* generated byte sequence and value bounds, stages two independently verified snippets, then copies them into distinct generation-owned CPL3 code pages. The page-table entries are user RX, stacks are separate user RW, and kernel mappings remain supervisor-only.
- The bounded IRQ-preemptive Ring 3 scheduler runs independent Franc-compiled programs in separate CR3 roots, handles a real user #PF in A, keeps B runnable across PIT switches, retires A, reclaims **14 leased pages**, and launches a new generation of Franc programs. The host shell remains usable after recovery.
- **Acceptance:** `FRANC_TEST_USER_COMPILED=1 python3 stage4/qemu_irq.py stage4/native_seed.img`. Verified job `126225823053`, in addition to earlier proven job `126216670643`.

**Important limits:** F3 is a real *but deliberately restricted* user-language compiler, not arbitrary full Franc/JIT execution at CPL3; no FPU/SIMD state virtualization, dynamic user loader, generic filesystem user syscalls, guard-page-backed general processes or production hardware portability is claimed. The older native REPL/JIT still runs trusted developer source with kernel privilege; installed packages use the restricted audited CPL3 path instead.

## U3 — native offline package install, update, rollback and uninstall (QEMU accepted)

- Portable `franctxt/packages.py` defines canonical `franctxt 1` package identity, semantic version, pinned dependencies, ordered source inventory, exact raw source SHA-256 and a bounded `package.generation` epoch. Host planning rejects digest tampering, path/filename escaping, cycles, duplicate files, version conflicts and capacity overflow.
- Native `lib/pkg.frac` implements **two fixed local package IDs** (`base` and `app`), each with a **single <=2047-byte source** and **two source+manifest banks**. A new generation is written to the inactive bank and published only after source and manifest verification; selection falls back to the older verified bank. The `app` package requires the exact installed `base` version and prevents uninstalling its dependency while the app remains installed.
- Native `pkg-sha256` verifies exact file bytes using an independent raw SHA-256 path, rather than accidentally hashing domain-prefixed Franctxt semantic data. `pkg-show` surfaces versions/generations; `pkg-install-verified`, `pkg-rollback` and `pkg-uninstall` implement the restricted lifecycle. The keyboard Packages interface exposes status, install/update, rollback, uninstall and isolated application launch. Installed program source is compiled and admitted as audited CPL3 bytes, **not silently evaluated in the trusted kernel JIT**.
- The disk model reserves two FRANCFS1 slots for system identity, two for offline upload staging and eight for the four package banks. User-facing source size/slot limits remain visible; this is not an unbounded repository.
- **Acceptance:** `python3 stage4/qemu_wave3_packages.py stage4/native_seed.img`, on the exact same seed image. QEMU tested **six cold boots**: install `base`, install and run dependent `app` in CPL3, upgrade and execute updated source, roll back and run the prior source, reject altered bytes before publication, uninstall both packages and verify that removal survives another cold boot. Verified job `126225822533`.

**Important limits:** The native v1 UI requires trusted local staging filenames; it is not a network package registry or a generic on-device multi-package dependency solver. Source hashes prove integrity against a supplied trusted manifest, not the authenticity of the publisher. FRANCFS1's directory sector is **not journaled**, so sector tearing and power-loss atomicity for uninstall/metadata updates are not claimed; copy-on-write bank selection protects the previously verified version during ordinary failed upgrades.

## Reproducibility, tests and later work

The same Wave 3 integration head passed 17 workflow suites, including the new paired F3/U3 QEMU workflow, native applications and IDE, Wave 1/2 isolation, network/UDP packet captures, BIOS and UEFI boots, seed generation 2/3 bootstrap and Franctxt build identity. The original 256-entry JIT definition cap was expanded to a **bounded 512 entries**, with tests preventing new modules from silently exhausting it. The pinned Franc assembly/bootstrap input seed and its lock remain unchanged.

**Wave 4 started:** [`FRANCOS_WAVE4_STARTED.md`](FRANCOS_WAVE4_STARTED.md) and [Wave 4 PR #15](https://github.com/Rsan0948/franc/pull/15) introduce bounded reusable networking/storage service words and a shared 320x200 VGA/serial interaction vocabulary. The initial Wave 4 dedicated QEMU suite passed; **the full cross-app consolidation and v1 demonstration are still outstanding.**
