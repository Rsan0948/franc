# FrancOS v1 — Wave 3 started (F3 + U3)

The binding release contract remains [FRANCOS_V1_DUAL_TRACK_ROADMAP.md](FRANCOS_V1_DUAL_TRACK_ROADMAP.md). This document is a factual handoff for **the initial Wave 3 implementation**, not a Wave 3 completion certificate.

## F3: Franc-authored isolated-user-code pipeline

- `lib/user_aot.frac` implements the first restricted Franc-language compiler for unprivileged x86-64 bytes. Accepted exact program shapes are `def main N count fault ;` and `def main N count again ;`, where `N` is an integer from 1 through 255.
- The compiler emits at most 36 bytes for these templates into the reserved `ide-buffer + 3072` area within the existing 4KiB IDE scratch reservation. It does not use the privileged Stage 2 JIT helpers as a generated program dependency. Input outside the grammar is rejected before emission.
- The first native QEMU contract calls `user-compile` on valid and invalid Franc source, checks emitted length, reads real opcode bytes from scratch, and confirms rejection of zero counts and unknown tokens.
- **Next mandatory F3 step:** Copy this checked byte span into an actual generation-owned RX CPL3 page, schedule two *Franc-compiled* user programs in separate CR3 contexts, fault A, keep B runnable, reclaim A and launch a third Franc program. This needs an explicit copy/authorization API, executable-range validation and syscall ABI compatibility tests.
- **Not yet done:** Running these Franc-generated bytes under Ring 3, general Franc language coverage in user mode, memory-safe arbitrary user programs, FPU/SIMD context switching, or package/file syscalls.

## U3: offline, verifiable package definitions

- `franctxt/packages.py` defines a canonical `franctxt 1` manifest profile for package ID, semantic version, pinned dependencies, up to four 2,047-byte source files and individual SHA-256 digests.
- The host-side *pure* planner validates content before producing a dependency-ordered install plan: paths and names cannot escape the namespace, reserved `kernel.franctxt` / `system.franctxt` are protected, missing/conflicting versions and cycles fail closed, duplicates and over-capacity plans are rejected.
- Maximum available package file slots are presently **10**, since FRANCFS1 contains 12 directory slots with two reserved system entries. The planner must include any proposed metadata files in a future native slot accounting implementation.
- **Next mandatory U3 step:** Implement a native FrancOS package manifest viewer and a disk-transaction protocol for install/update/uninstall/rollback. Every write must validate the exact digest, identity and dependency closure, and interruption at each stage must leave either the old installed set or the fully new installed set available after reboot. No trusted kernel JIT execution of an untrusted package.
- **Not yet done:** Writing these plans to native FRANCFS1, an on-device dependency solver, update/rollback/replay, transport/discovery, or end-to-end native app execution.

## Regression-proofing the source bundle

Wave 3 adds new JIT definitions to a mature native application bundle. The prior runtime reserved **256** mutable dictionary entries; the updated bound is **512** entries with `512 × 24` bytes for nodes and `512 × 64` bytes for names. The `test_user_aot_contract.py` contract counts bundled definitions against that bound. A strict native QEMU test checks every newly added user emitter word with `s2-find`, because the historical loader increments its compiled-line count even when a line fails.

Expanding the runtime assembly dictionary does **not** change the pinned Franc compiler/AOT seed source list or its lock; no changes to `bootstrap_seed.S` should be introduced by this Wave 3 foundation.
